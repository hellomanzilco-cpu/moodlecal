# Student interface and languages

The main menu contains Assignments, Sync, More and Settings. Opening Start or Main menu shows a compact assignment summary from the saved snapshot. Extra planning views remain available through More and existing commands. The dashboard does not request a Moodle profile. Each rendered task shares one private assignment capability between its linked title and native Telegram button; replies containing those capabilities are not cached in reply history.

English, Uzbek (Latin script), and Russian are available under Language in the welcome menu and Settings. Existing accounts start in English. The choice is stored per student in a SQLite column; a migration preserves connections, snapshots, deadlines and preferences. Reconnecting preserves the selected language. English and translated button labels both work, including old Telegram keyboards. Invalid language values cannot change permissions or ownership.

Student menus, dashboard, assignment lists, connection and assignment windows, privacy text, sync outcomes, reminders and submission receipts use the chosen language. Teacher-provided course titles, task instructions, submission statements, file names and grade values stay in their original form. Operator reports and advanced command syntax remain in English; Moodle-generated restriction details and uncommon provider errors may also remain in their original language. The translation dictionaries are local application text: no translation model receives credentials, coursework or other student data.

Language preferences do not affect authentication, consent, allowed file types, requirements, submission confirmation, group/timed-task restrictions, or strict submission-status checks. Missing required status data blocks connect/sync and preserves the last saved snapshot. Optional coverage warnings remain visible. Date formatting uses the chosen locale and the student's time zone.

Privacy messages explain password handling, encrypted access tokens, aggregate statistics, separate support diagnostics, optional profile sharing and disconnect behavior. They do not promise absolute security or deletion of Moodle work, delivered Telegram messages or retained encrypted backups. The privacy view links to the policy in the selected language. Profile sharing stays off until a separate, expiring confirmation is given.

Validation covers tenant isolation, old button compatibility, translated HTTP pages and connection failures, safe task links, unchanged Moodle content, language persistence and migration, translated heavy-action queue classification, and parsing the generated JavaScript for all three languages. A student pilot in Telegram is still needed to assess wording and layout on real phones before a wider release.
